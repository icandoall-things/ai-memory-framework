# 双系统 AI 记忆架构

一台机器上装了 Windows 和 Ubuntu，两边各跑一个 Claude Code。两个系统不能同时开机，各自的记忆库
躺在各自的分区上，一边的 Claude 读不到另一边记了什么。

结果是重复教学。同一句「跑 Python 用哪个解释器」在 Windows 上教过，重启进 Ubuntu 还得再教一遍。
比重复更麻烦的是版本漂移，两边对同一件事的记忆可能互相打架，而两边都以为自己是在照规矩办事。

这套框架把记忆按「换个系统还成立吗」拆成三层，全部放在两个系统都能读写的盘上。两边的全局记忆
文件退化成两行 `@引入`，具体内容一概不放本地。

## 三层结构

```
D:\AI-MEMORY\
├── 通用MEMORY\      ← 两个系统都加载
├── WindowsMEMORY\   ← 只有 Windows 加载
└── UbuntuMEMORY\    ← 只有 Ubuntu 加载
```

| 层 | 自动加载于 | 装什么 |
|---|---|---|
| 通用 | 两个系统 | 换系统仍然成立的规矩，比如沟通风格、记忆写法、工具存放位置 |
| Windows | Windows | 只在这个系统上做的事，比如 Windows 的命令行与外设踩坑 |
| Ubuntu | Ubuntu | 同上，Ubuntu 侧的那些，比如装机约束、apt 与镜像源 |

分层的判定只有一句话。**换到另一个系统，这条还成立吗。** 成立就进通用层，不成立就进各自那层。

分层只决定「哪几层被自动加载」。三层文件都在同一个盘上，两个系统都读得到。任务做到一半发现
需要别层的知识，随时跨层去读，说一声即可，规则不必写死。

## 接任务先路由

每次接到任务，先做完四件事再动手。

1. 判断任务载体属于 Windows 专属、Ubuntu 专属、跨系统，还是纯通用
2. 说一句读了哪几层，例如「这是 Windows 任务，我读了通用加 Windows」
3. 判断该调哪个 skill，先把判断说出来再调
4. 干完有新规矩就写回对应那层，并在该层 `MEMORY.md` 里加一行

第二、三步是做给人看的。用户需要知道这件事是按哪几层的知识办的，也需要知道为什么动用了某个 skill。
细则见 [docs/03-接任务先路由.md](docs/03-接任务先路由.md)。

## 怎么接上

1. 把 `template/` 里的三层目录复制到那个共享盘，例如 `D:\AI-MEMORY\`
2. 改两个系统的全局记忆文件，各写两行引入。Windows 引「通用 ＋ Windows」，Ubuntu 引「通用 ＋ Ubuntu」
3. 以后新记忆写进对应层的域子目录，一条一主题，顺手在索引里加一行

接线命令、目录联接的建法、盘没挂载时会发生什么，都在 [docs/06-接线与坑.md](docs/06-接线与坑.md)。

## 让 AI 帮你接上

上面那三步可以整段交给 AI。把下面这段话复制给那台机器上的 Claude Code，它会自己判断这是哪一侧、
该往哪接。它做的事跟上面那三步一样，多出来的部分是在几个地方设了卡，要它停下来先报备再动手。

```text
我要在这台机器上接上「双系统 AI 记忆架构」。仓库路径是 <仓库路径>。

如果你看到上面那个路径还带着尖括号，说明我没替换。别猜，也别自己挑一个位置放。
先看你现在的工作目录是不是就是仓库，再翻翻常见的下载位置。找到了报给我确认。找不到
就问我，或者让我把它 clone 到你指定的目录。clone 地址是
https://github.com/icandoall-things/ai-memory-framework

先把仓库里的 docs/ 六篇和 template/CLAUDE.md.example 读完，按它的术语办事，别自己
另起一套叫法。

然后照下面走。每步做完停下来报结果，我确认了再继续。凡是涉及覆盖、删除、改用户目录
的操作，先说清你要动哪个路径，等我点头。

1. 判断这是哪一侧。说清是 Windows 还是 Ubuntu，依据是什么。

2. 定共享盘。Windows 侧要找一个两个系统都能读写的分区。Ubuntu 侧那个分区必须已经
   挂载，而且是开机自动挂载，软链接指向一个经常不存在的路径会悬空。拿不准就问我，
   不要随便挑一个盘。要改 /etc/fstab 的话，先把改动内容给我看，这一步弄错会影响开机。

3. 报路径。说出你打算用的共享路径，例如 D:\AI-MEMORY\ 或
   /media/<你>/<卷标>/AI-MEMORY/。我确认后再往下。

4. 查现状。那个路径下如果已经有 AI-MEMORY，先找有没有 部署记录.md，有就读它，你会
   知道另一侧当时是怎么接的。然后把现有结构报给我，不要覆盖。没有才继续。

5. 铺骨架。把 template/ 里的三层目录复制过去。

6. 改全局记忆文件。Windows 是 C:\Users\<你>\.claude\CLAUDE.md，Ubuntu 是
   /home/<你>/.claude/CLAUDE.md。动手前先把这个文件现在的内容完整贴给我看，确认里面
   没有别的东西会被挤掉。

7. 只写两行。往里面写两行 @引入，引「通用 ＋ 本侧那一层」。具体规则一条都不要抄进去，
   抄了就会出现第二个版本，这正是这套框架要消掉的东西。

8. 问联接。问我是否要把新记忆直接落到共享盘，Windows 用 mklink /J，Ubuntu 用 ln -s。
   这一步要动用户目录，先说明你要动哪个路径。

9. 写回执。在共享盘根目录写一份 部署记录.md，记下这台机器是哪一侧、共享路径是什么、
   建没建联接、全局记忆文件的完整路径、部署日期。另一侧已经写过就补上自己这一段，
   不要重写整份。

做完自检四条，逐条给结论，不要笼统说「已完成」。

- 全局记忆文件里除了引入行和一句说明，没有别的规则
- 两行 @引入指向的路径真实存在，而且是文件不是目录
- 共享盘上三层目录齐全，每层都有 MEMORY.md
- 部署记录.md 写好了，内容对得上这次实际做的事

哪条不成立就直接说哪条不成立，不要替我圆过去。
```

## 目录里有什么

| 路径 | 内容 |
|---|---|
| `docs/` | 六篇说明，从动机一路讲到接线 |
| `template/` | 可以直接复制的空骨架，不含任何真实条目 |
| `assets/三级架构效果图.html` | 三层架构的可视化图，浏览器直接打开，自带深色模式。也可[在线看](https://icandoall-things.github.io/ai-memory-framework/assets/三级架构效果图.html) |

## 这套东西的边界

它解决的是两个系统各记各的、换个系统就要把规矩重讲一遍的问题。它不解决记忆本身写得好不好。
一条只描述此刻状态的记忆，放在哪层都会烂掉。记忆该怎么写，见
[docs/05-写记忆的规矩.md](docs/05-写记忆的规矩.md)。
