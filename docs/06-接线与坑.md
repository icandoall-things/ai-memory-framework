# 06 接线与坑

## 全局记忆文件里只留引入行

每个系统的全局记忆文件负责把「通用 ＋ 自己那层」引进当前会话。

| 系统 | 全局记忆文件 | 引入哪两层 |
|---|---|---|
| Windows | `C:\Users\<你>\.claude\CLAUDE.md` | 通用 ＋ Windows |
| Ubuntu | `/home/<你>/.claude/CLAUDE.md` | 通用 ＋ Ubuntu |

内容就两行 `@引入`，加上一句说明这是哪一侧、分了哪几层。具体规则一概不写在这里，写了就会出现
第二个版本。

```
@D:\AI-MEMORY\通用MEMORY\MEMORY.md
@D:\AI-MEMORY\WindowsMEMORY\MEMORY.md
```

`template/CLAUDE.md.example` 是可以直接改的样板。

## 让新写的记忆自动落到共享盘

引入方式解决了「读得到」，没解决「写得对」。自动记忆功能默认往自己那边写，两个系统各写各的，
用久了仍然会散开。

彻底的做法是把两边的原生记忆目录直接指到共享盘的对应层。

Windows 用目录联接。`/J` 建的是联接，不是符号链接，不需要管理员权限。

```
cmd /c mklink /J "C:\Users\<你>\.claude\projects\<项目目录名>\memory" "D:\AI-MEMORY\WindowsMEMORY"
```

Ubuntu 用软链接，因为 Linux 建不了 Windows 联接。

```
ln -s "/media/<你>/<挂载点名>/AI-MEMORY/UbuntuMEMORY" ~/.claude/projects/-home-<你>/memory
```

做完这一步，新记忆直接落在共享区，不会再漂移。

## 坑一，盘没挂载时是静默失效

Ubuntu 侧的引入行指向挂载点。如果那个分区没被挂载，这两行不会报错，它们只是什么都不引入。
表现是 Claude 看起来正常干活，但完全不知道三层记忆的存在。

所以 Ubuntu 侧要先把那个分区设成开机自动挂载，再建软链接。软链接指向一个经常不存在的路径，
会悬空。

## 坑二，项目目录名是路径推导出来的

Claude Code 按「从哪个目录启动」给记忆分文件夹。Windows 上是 `C--Users-<你>` 这种把路径里的
分隔符换成连字符的形式，Ubuntu 上是 `-home-<你>`。建联接前先确认实际目录名，猜错会建出一个
没人读的目录。

## 坑三，共享盘上的东西不会被自动扫描

Claude Code 只会扫描自己用户目录下的 `skills/` 和项目的 `.claude/`。放在共享盘上只是「存着」，
不等于生效。想让共享盘上的内容生效，必须通过引入行、目录联接或软链接接到用户目录下。

这条在放技能库时格外容易踩，把技能放进共享盘就以为装好了。

## 坑四，留一份说明在两边都够得着的地方

这套架构本身的说明应该放在共享盘上，两个系统都能打开。放在某一侧的用户目录里，另一侧就看不到，
等于又制造了一次刚才花力气消灭的信息不对称。
