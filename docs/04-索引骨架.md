# 04 索引骨架

## 每层一个入口

每一层的根目录下有一个 `MEMORY.md`，它是这层的入口，也是唯一会被自动加载的索引文件。
三个层的 `MEMORY.md` 用同一套骨架，分 A、B、C 三段。

| 段 | 内容 | 会不会过期 |
|---|---|---|
| A | 长期成立的条目，任何任务都适用 | 不会 |
| B | 域路由表，按任务里的关键词指向某个域 | 表本身不会 |
| C | 状态类快照的指针 | 会，且必须标注 |

## A 段，长期成立的条目

一行一个条目，格式是「本地链接，破折号，一句话说明」。这一句话要写到能据此判断要不要打开，
不能写成「关于 X 的说明」。

## B 段，域路由表

任务多起来之后，一层里的条目会散成十几个主题。域路由表把主题归成域，每个域一个子目录，
配一份 `_INDEX-*.md`。

表的第二列写的是关键词，第三列是指向该域索引的链接。关键词那一列不是装饰，它承担了主要的
判断工作。判不准归属时看这一列，不要因为拿不准就把整个目录扫一遍。

零散的、不值得单开一个域的主题，直接留在 A 段就行。域是给成规模的主题用的。

## C 段，状态类快照

指向那些描述「现在到哪了」的文件。指针旁边必须写明这是会过期的内容，用的时候以文件里写的
日期为准，不要往后外推。

C 段是唯一允许放会过期内容的地方，而且只能以指针形式出现，正文仍然在域子目录里。

## 域子目录与一条一主题

核心规则是一条记忆一个文件，不要把几条互相独立的约束塞进同一个文件。

这条规则听起来啰嗦，但它解决的是「改了其中一条，整份文件都得重读」的问题。一个文件里装了八条
互不相关的约束，其中一条过时了，读的人无从判断另外七条还作不作数。

一个反例是早期 Ubuntu 层的四个文件，每个文件装了好几条独立约束，跟 Windows 层的颗粒度对不上。
两边同形是硬要求，跨层读的时候结构一致能省掉一次适应成本。

## 读法

拿到一个任务，读的路径固定。

1. 读该层 `MEMORY.md` 的 A 段，看有没有直接相关的长期条目
2. 读 B 段的路由表，挑**一个**域，打开它的 `_INDEX-*.md`
3. 在那个域里只读用得上的那几条

挑一个域是关键。跨域任务才读多个域，而不是把每个域的索引都翻一遍。

## 索引纪律

- 新增条目，就在它所属域的 `_INDEX` 里加一行；必要时再在系统层 `MEMORY.md` 的 A 段加一行
- 一个条目只索引一次。同一个文件不要在两层索引里各写一遍，那样必然会有一处先过期
- 会过期的状态不放通用层，也不进 A 段
- 跨层引用用相对路径，例如 `..\通用MEMORY\xxx.md`
- 删掉某个文件时，回头检查别的记忆里有没有指向它的链接。指向已删文件的指引比单纯过时更危险，
  照着走会直接报错
