# 02 三层架构

## 目录长什么样

```
D:\AI-MEMORY\
├── 通用MEMORY\
├── WindowsMEMORY\
└── UbuntuMEMORY\
```

三个目录平级，都放在那个共享盘上。盘符不一定是 `D:`，只要两个系统都能读写、且在一个系统重装后
依然存在即可。NTFS 分区通常是最省事的选择。

## 每层装什么

| 层 | 自动加载于 | 装什么 |
|---|---|---|
| 通用 | 两个系统 | 沟通风格、记忆写法、技能库位置、双系统之间的约定 |
| Windows | Windows | 只在这个系统上发生的任务与踩坑 |
| Ubuntu | Ubuntu | 同上，Ubuntu 侧的那些 |

三层的内部结构完全同形，都用「域子目录 ＋ `_INDEX-*.md`」组织，索引骨架也都是 A/B/C 三段。
两个系统层必须同形，否则跨层查找时得先判断自己在哪一层，再切换一套记忆方式。

## 分层的判定

判定尺子只有一句话。**换到另一个系统，这条还成立吗。**

- 成立，进通用层。例如「长文写作的硬禁令清单」。
- 不成立，进它所属的那个系统层。例如「这台笔记本的键盘 IRQ1 失效」。

有一条容易答错的，是「装到哪一步了」这类状态。换到另一个系统它当然不成立，但它也不该待在任何
一层。会过期的状态根本不该写成记忆，理由见 [05-写记忆的规矩.md](05-写记忆的规矩.md)。真要留，
就放在它所属的系统层，别塞进通用层。

## 一个高频错误

把「跨系统任务」当成一层，于是任务收尾时留下的所有东西都留在原来的地方。

曾经有一个分盘任务，做完之后留下了两条待办，一条是 Windows 上要重装某个游戏平台，一条是
Windows 上要清理几个残留的卸载项。这两条当时都挂在 Ubuntu 层的收尾文件里，因为它们是从那个
任务里长出来的。

正确的做法是按内容归属，不按任务归属。这两条的内容都只在 Windows 上发生，就该落在 Windows 层，
跟它们从哪个任务里长出来没有关系。后来这两条被直接删掉了，因为待办本来就不该写成记忆。

## 分层不等于权限墙

这一点值得单独说，因为它反直觉。

三层目录都在同一个盘上，两个系统都读得到。分层决定的只是**默认自动加载哪几层**，它不构成访问限制。
在 Ubuntu 上做视觉模块，需要用到手机拍照的约束条件，而那条约束记在 Windows 层的课程作业域里，
直接过去读就行，说一声即可。

把访问路径写死成「我在 Ubuntu，所以我读不到 Windows 层」是很容易犯的错，代价是明明记过的东西
却答不出来。
