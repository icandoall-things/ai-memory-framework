01

任务进来先路由：这条活儿归哪个系统？

每接一个任务都走一遍这几步
你下达任务
第 1 步 · 判断「任务载体」
看它要动的文件、要跑的命令、要用的软件在哪个系统上
Windows 专属 Windows 上的编译与打包
外设·驱动·系统设置·PowerShell 读 通用 ＋ Windows 记忆
Ubuntu 专属 ROS 工作区 · 内核模块编译
apt 换源 · 装机分区 读 通用 ＋ Ubuntu 记忆
跨系统 共享盘上的工具链 · 技能库
双系统时间与 RTC · 这套记忆本身 三层全读
纯通用 写作与改稿 · 沟通偏好
报告规矩 · 记忆怎么写 只读 通用
判不准的时候按「跨系统」处理。多读一层的代价，小于答错的代价。
第 2 步 · 判断该调哪个 skill
扫技能列表 → 说出调哪个、为什么 → 再动手
第 2 步要出声，长这样：「这是 Ubuntu 任务，我读了通用＋Ubuntu」「这个用 markitdown 更合适」。
这两句话是做给人看的。判断错了，用户当场就能发现，不必等到答案跑偏才回头排查，而这句的成本几乎为零。
第 3 步 · 执行，然后把新规矩写回去
换个系统还成立 → 写通用层；只在某一个系统成立 → 写该系统层。写完在该层 MEMORY.md 索引里加一行
02

三层记忆：各自装什么

判定标准只有一句话 —— 换个系统还成立吗？

通用 MEMORY

<共享盘>\AI-MEMORY\通用MEMORY\
判定：换到另一个系统，这条还成立吗？
  • 怎么跟你沟通 用大白话还是术语，要不要先给结论
  • 记忆的写法 只写长期约束，不写「此刻状态」
  • 工具装在哪个目录 统一放一处，别塞进项目文件夹
  • 写作与改稿的规矩
  • 密钥不进任何文档
  • 报告要保留原始图表与原始数据

Windows MEMORY

<共享盘>\AI-MEMORY\WindowsMEMORY\
判定：只在 Windows 上做的事
  • Windows 侧的项目 按域分目录，比如「工具链」「外设」
  • 命令行与路径规矩 盘符、路径长度、编码
  • 驱动与外设排障
  • 系统层能装什么、不能装什么
  • 某个任务的当前进度 会过期，尽量别写

Ubuntu MEMORY

<共享盘>\AI-MEMORY\UbuntuMEMORY\
判定：只在 Ubuntu 上做的事
  • ROS 工作区与编译方式
  • 驱动与内核模块 比如某个设备要改内核参数
  • 装机 · 分区 · apt 与镜像源
  • 开发环境版本 node、python、工具链的约定
  • Ubuntu 侧当前状态 会过期，尽量别写
判定演练 同一条事实，落到哪一层
一条记忆去哪层为什么
「长文结尾不要用『总的来说』」 通用 换到另一个系统照样成立，跟跑在哪个系统无关
「这台笔记本的键盘中断会丢，要改内核参数」 Ubuntu 只在这台机器的那个系统上成立，换过去就不对了
「跑脚本一律用某个指定解释器」 通用 是开发约定，不是某个系统的特性
「某软件现在装到第 3 步了」 哪层都别放 会过期。过期的状态不该写成记忆，真要留就写进它所属的系统层，别塞进通用层
「共享盘上的工具链怎么装」 跨系统，写通用 任务跨两个系统，但内容两边都成立，按内容归属落层，不按任务归属
一个高频错误：把「跨系统任务」当成一层，于是任务收尾时留下的所有东西都留在原来的地方。
分层的依据是内容归属，不是任务归属。某条内容只在 Windows 上发生，哪怕它是从 Ubuntu 侧的任务里长出来的，也该落进 Windows 层。
03

文件放哪 · 两边怎么接上

全放共享盘：两个系统都读写得到，重装一侧也不会丢 
D:\AI-MEMORY\              ← 共享盘（盘符不一定是 D:）
├── 通用MEMORY\
│   ├── MEMORY.md          ← 索引 + 路由表（第一入口）
│   ├── 沟通风格.md
│   └── 记忆怎么写.md
├── WindowsMEMORY\
│   ├── MEMORY.md          ← 索引
│   ├── 外设与驱动\
│   │   ├── _INDEX-外设与驱动.md
│   │   └── <一条一主题>.md
│   └── 工具链\ …
└── UbuntuMEMORY\
    ├── MEMORY.md          ← 索引
    ├── ROS2\ …
    └── 装机与分区\ …
Windows 侧
C:\Users\<你>\.claude\CLAUDE.md   @D:\AI-MEMORY\通用MEMORY\MEMORY.md   @D:\AI-MEMORY\WindowsMEMORY\MEMORY.md
Ubuntu 侧
/home/<你>/.claude/CLAUDE.md   @/media/<你>/<卷标>/AI-MEMORY/通用MEMORY/MEMORY.md   @/media/<你>/<卷标>/AI-MEMORY/UbuntuMEMORY/MEMORY.md
要点：那两行 @ 就是「只读自己那两份」。内容一条都不要抄进全局记忆文件， 抄了就会出现第二个版本，两边迟早打架 —— 这正是这套框架要消掉的东西。
坑：共享盘没挂载时，Ubuntu 那两行会静默失效，不报错，记忆看起来就是空的。 所以要么开机自动挂载，要么启动前点一下那个盘。
04

动手前常问的三个问题

这三处的取舍，决定了整套东西好不好用
Q1

系统层的记忆放哪？

放共享盘，两边都能读到，在 Ubuntu 上也能替 Windows 的任务做判断；各留本机，对方完全看不见，等于白记。

都放共享盘（推荐）
各留本机（C: / ext4 各一套）
Q2

判完要不要先说一声？

静默判断省事，但判错的时候用户不一定看得出来，只能等答案跑偏了再回头查。

先说一句「这是 Windows 任务，我读了通用＋Windows」再干
静默判断，直接干
Q3

现有的记忆怎么搬？

机器上多半已经攒了一堆记忆条目，按「会不会随系统变」拆进三层即可，不必推倒重来。

一次拆完，拆完留一张「旧条目 → 新层」的对照表
先只搭空架子，以后慢慢搬
